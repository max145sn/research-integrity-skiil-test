| Genotype notation | Superscript `−/−` flattens to inline `-/-` | **CAUTION** for automated parsing |

### Known extraction hazards for downstream use

1. **Scientific notation loses its minus sign.** Exponents extract as `10–15`, `10–6`. Any regex harvesting P values must treat the en-dash as a negative exponent or it will read *P* = 10¹⁵.
2. **Figure-embedded P values are positionally separated from their panel labels.** In the extracted stream, printed statistics appear as bare `P = 0.0004` lines adjacent to axis labels, with the panel letter often lines away. Panel attribution from the text layer alone is unreliable.
3. **`find_tables()` is not detecting tables.** The 13 hits on page 8 are immunoblot panel borders. Table extraction from this PDF should be skipped entirely.
4. **Extended Data is invisible to text mining** (see § 3).

## 7. Recommendations

### Preprocessing
- Use `pdfplumber` or `pymupdf` for the text layer; do **not** run OCR on pages 1–13 (it would degrade a clean layer).
- **Do** run OCR, or obtain the original figure files, if Extended Data content is needed — pages 14–21 cannot be mined otherwise.
- Normalise en-dash → minus before parsing any numeric expression; re-join `10–<n>` to `10^-<n>`.
- Discard `find_tables()` output for this document.

### Appropriate analyses
- Section segmentation and claim extraction over pages 1–13 (this is what the repository's `claim-grounding` and `paper-claim-audit` skills consume).
- Figure-legend parsing for stated *n* and statistical tests — reliable, since legends live in the text layer.
- Panel-level P-value attribution — only with the typeset figures visible, not from text alone.
