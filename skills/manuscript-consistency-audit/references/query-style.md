# Author query style

> The full rule, with worked examples, lives in `SKILL.md` under
> **Output format → Part 2 → Locate, don't diagnose**. This file is the short
> reference card.

Two deliverables, written for different readers. The asymmetry is deliberate:
**the editor gets the whole derivation, the author gets a pointer.**

## Part 1 — Findings report (for the editor)

Everything: the exact quoted text, what it conflicts with, the arithmetic shown,
how it was identified. Ordered by strength, demonstrable contradictions first.
Close with a short **checked but not raised** list, one line each with the reason.

## Part 2 — Author queries

### Locate, don't diagnose

A query sends the author back to a specific place to re-examine their own work.
It does not hand them a correction to paste in. An author told "8.61 should be
8.16" edits one cell; an author told "the film-free insertion loss in
Supplementary Table 2 may not be consistent with its source data" goes back to
the measurement, works out why, and checks whether the same slip hit anything
else — which is the check the journal actually wants.

Name **where** and **which quantities**. Say an inconsistency *appears* to exist
between the named locations. Ask for a check.

Do not supply:

- your recomputed value, or any arithmetic
- which of the conflicting values you believe is correct
- the mechanism you diagnosed — transposition, wrong denominator, off-by-one
  formula range, mislabelled column

Include a specific value only to identify *which* instance you mean, never as
evidence. If a query runs long, you are explaining rather than pointing.

### Three exceptions

1. **The search would otherwise be too wide.** Narrow it by saying what *does*
   reconcile: "the entries for the device with the film appear reproducible;
   those without the film may need re-checking."
2. **Not actionable without the reasoning.** "Please check the detector" is
   unanswerable — the author needs to see that an FID does not respond to H2.
3. **Nothing to work out.** Typos, duplicated sentences, empty source-data
   sheets. State these plainly.

### Voice

Enquiring, not accusatory. "Can you please double-check...", "Please confirm...",
"It appears there may be...". Prefer "may not be consistent" over "does not
match". Where an innocent explanation exists, offer it as the thing to confirm.

### Formatting

One unbroken paragraph per bullet. A follow-on query may open with "Related to the above," or similar, but do not overuse it. Keep units and range punctuation consistent throughout.
